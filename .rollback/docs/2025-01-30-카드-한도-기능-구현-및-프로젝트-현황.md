**작성일**: 2025-01-30

## 1. 신규 구현: 카드 한도(CardLimit) 기능

카드별 월간 한도를 설정하고, 거래 알림 시 한도 대비 사용 현황을 함께 제공하는 기능을 구현함.

### 1.1 추가된 파일

| 파일 | 경로 | 설명 |
|------|------|------|
| `CardLimit.kt` | `domain/card/entity/` | 카드 한도 JPA 엔티티 |
| `CardLimitRepository.kt` | `domain/card/repository/` | Spring Data JPA 리포지토리 |
| `CardLimitService.kt` | `domain/card/service/` | 한도 CRUD 및 사용액 집계 비즈니스 로직 |
| `CardLimitController.kt` | `domain/card/controller/` | REST API 컨트롤러 |
| `CardLimitDto.kt` | `domain/card/dto/` | 요청/응답 DTO |
| `card-limits.http` | `src/test/http/` | HTTP 테스트 파일 |

### 1.2 CardLimit 엔티티

- **테이블**: `card_limits` (스키마: aguagu)
- **필드**: id, cardCompany, cardLastFourDigits, monthlyLimit, createdAt, updatedAt
- **Unique 제약**: (cardCompany, cardLastFourDigits)

### 1.3 API 엔드포인트

| 메서드 | 엔드포인트 | 설명 |
|--------|-----------|------|
| POST | `/api/v1/card/limits` | 카드 한도 생성/수정 (upsert) |
| GET | `/api/v1/card/limits` | 전체 한도 조회 |
| GET | `/api/v1/card/limits/{id}` | 단건 한도 조회 |
| DELETE | `/api/v1/card/limits/{id}` | 한도 삭제 |

### 1.4 한도 관리 흐름

```
1. POST /api/v1/card/limits로 한도 설정
   ↓
2. (cardCompany, cardLastFourDigits) 조합으로 기존 한도 조회
   ↓
3. 존재 → monthlyLimit 업데이트 / 미존재 → 신규 생성
   ↓
4. 현재 월 사용 금액 집계 (sumAmountByCardAndPeriod)
   ↓
5. 한도, 사용액, 잔여 한도 포함 응답 반환
```

## 2. 프로젝트 전체 현황

### 2.1 패키지 구조

```
com.woo.server
├── common/
│   ├── config/TelegramProperties             # Telegram 설정 속성
│   ├── enums/CardCompany                     # 카드사 열거형 (10개)
│   └── notification/TelegramNotificationService  # Telegram 알림 서비스
└── domain/card/
    ├── controller/
    │   ├── CardTransactionController          # 거래 REST API
    │   └── CardLimitController                # 한도 REST API
    ├── service/
    │   ├── CardTransactionService             # 거래 비즈니스 로직
    │   └── CardLimitService                   # 한도 비즈니스 로직
    ├── dto/
    │   ├── CardMessageRequest                 # 카드 문자 요청 DTO
    │   ├── CardTransactionResponse            # 거래 응답 DTO
    │   └── CardLimitDto                       # 한도 요청/응답 DTO
    ├── entity/
    │   ├── CardTransaction                    # 거래 엔티티
    │   └── CardLimit                          # 한도 엔티티
    ├── repository/
    │   ├── CardTransactionRepository          # 거래 리포지토리
    │   └── CardLimitRepository                # 한도 리포지토리
    └── parser/
        ├── CardMessageParser                  # 파서 인터페이스 + ParseResult
        ├── SamsungCardParser                  # 삼성카드 파서
        └── CardParserFactory                  # 파서 팩토리
```

### 2.3 구현 상태 요약

#### 구현 완료

- 카드 결제 문자 수신 및 파싱 (삼성카드)
- 거래 내역 CRUD 및 조회 (전체, ID별, 카드사별, 성공/실패별)
- 중복 거래 방지 (cardCompany + amount + transactionDate + merchantName)
- 파싱 실패 시 원본 메시지 저장
- Telegram Bot 실시간 알림 (성공/실패 케이스)
- 카드 한도 설정 및 조회 (upsert 방식)
- 월간 사용액 집계 및 잔여 한도 계산
- HTTP 테스트 파일 3종 (card-transactions, card-limits, telegram-test)

#### 미구현

- 날짜 범위 필터링 API (startDate, endDate 쿼리 파라미터)
- 현대, KB, 신한, 롯데, 하나, 우리, NH, BC 카드 파서
- 비즈니스 로직 단위 테스트 / 통합 테스트

### 2.4 발견된 이슈

1. **card-transactions.http**: `receivedAt` 필드가 남아있으나 DTO에서는 `phoneNumber`로 변경됨 → 수정 필요
2. **card-limits.http**: URL이 `http://localhost:8080`으로 하드코딩됨 → `{{host}}` 변수 사용 권장
