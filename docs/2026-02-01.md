# 2026-02-01 누적금액 정산기간 기준 변경 및 버그수정

---

## 1. 누적금액 표시 기준 변경

Telegram 알림의 누적금액을 카드사 원본 값 대신 신용카드 정산기간 기준 합산액으로 변경.

| 항목 | 변경 전 | 변경 후 |
|------|---------|---------|
| 누적금액 소스 | `tx.accumulatedAmount` (카드사 SMS 원본) | `limitInfo.usedAmount` (정산기간 합산액) 우선, 없으면 SMS 원본 fallback |

---

## 2. 하나카드 마스킹 카드번호 역매칭 수정

### 문제

하나카드 SMS의 마스킹 카드번호(`7*2*`)로 신용카드 매칭 실패 → 거래가 마스킹 값으로 저장, 한도 사용액 0원 표시.

### 해결

- `CreditCardRepository.kt`: LIKE 패턴 쿼리 `findByCardCompanyAndLastFourDigitsLike()` 추가
- `CreditCardService.kt`: `buildLikePattern()` 함수 추가 (`"7*2*"` → `"7_2_"`)

```
SMS: "하나7*2*" → LIKE 매칭 "7_2_" → DB에서 "7929" 매칭 성공
→ 거래가 "7929"로 정규화되어 저장 → 한도 조회 정상
```

## 3. 거래일시 연도 판정 버그 수정

### 문제

파서의 `buildDateTime()`이 **분 단위**로 미래 판정하여, 당일 거래라도 SMS 시각이 현재보다 몇 분 앞서면 **작년으로 밀림**.

### 해결

3개 파서 모두 **날짜 단위(`LocalDate`)로 비교**하도록 변경:
- `HanaCardParser.kt`, `KbCardParser.kt`, `SamsungCardParser.kt`

---

## 4. 신용카드 결제일 입력 기능 추가

`CreditCardListView.vue`에 결제일 입력 필드 추가 (선택사항, 1~31). 백엔드는 이미 `paymentDay`를 지원하고 있어 변경 없음.
