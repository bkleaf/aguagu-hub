# 2026-02-08 멀티파트 SMS 해결, 신용카드 active 필드, 삼성카드 후불교통, 파싱실패 테이블 분리

---

## 1. 멀티파트 SMS 분할 전송 이슈 해결

### 문제

하나카드 결제 문자가 2건으로 분리되어 DB에 저장되고 파싱 실패됨.

| # | 저장된 메시지 | 결과 |
|---|--------------|------|
| 1 | `MG+ 하나7*2*승인 전*우 12,900원 ... 누적1,296` | 실패 ("원" 누락) |
| 2 | `,033원` | 실패 (인식 불가) |

### 원인

긴 SMS가 통신사에서 **멀티파트 SMS**로 분할 전송되고, 안드로이드 앱이 각 파트를 별도 API 호출로 전송.

### 해결

**안드로이드 앱 수정**: 멀티파트 SMS를 병합한 후 단일 API 요청으로 전송하도록 변경.

## 2. 신용카드 사용 여부(active) 필드 추가

### 변경 사항

- `CreditCard` 엔티티에 `active: Boolean` 필드 추가 (기본값: `true`)
- DTO Request/Response에 `active` 필드 추가
- 프론트엔드: 목록에 사용 여부 아이콘 표시, 등록/수정 폼에 체크박스 추가
- 동작: 단순 표시용 (`active=false`여도 거래 파싱 매칭에는 영향 없음)

### DDL

```sql
ALTER TABLE aguagu.credit_cards ADD COLUMN active BOOLEAN NOT NULL DEFAULT true;
```

## 3. 삼성카드 후불교통 파서 추가

### 문자 형식

```
[Web발신]
[삼성카드]6518
02월접수 후불교통
(버스+지하철+통행료)
합계 74,320원
```

### 변경 내용

`SamsungCardParser.kt` 수정:
- `POSTPAID_CARD_PATTERN`, `POSTPAID_AMOUNT_PATTERN`, `POSTPAID_MERCHANT_PATTERN` 정규식 추가
- `canParse()`: "후불교통" 키워드 추가
- `parsePostpaidTransport()`: 후불교통 전용 파싱 메서드 (거래일시 없음 → 현재 시간 사용)

### 삼성카드 지원 형식

| 형식 | 예시 | 비고 |
|------|------|------|
| 법인카드 | `삼성법인4300 766,120원...` | 잔여한도 포함 |
| 개인카드 | `삼성6518승인 전*우...` | 누적금액 포함 |
| 후불교통 | `[삼성카드]6518 02월접수 후불교통...` | 날짜 없음, 현재 시간 사용 |

## 4. 파싱 실패 테이블 분리

파싱 성공/실패 내역을 `card_transactions` 테이블 하나에서 관리하던 방식에서, 파싱 실패를 별도 테이블(`card_parse_failures`)로 분리.

### 신규 파일

| 파일 | 설명 |
|------|------|
| `entity/CardParseFailure.kt` | 파싱 실패 엔티티 |
| `repository/CardParseFailureRepository.kt` | 파싱 실패 리포지토리 |
| `dto/CardParseFailureDto.kt` | 파싱 실패 응답 DTO |

### 주요 변경

- `CardTransaction` 엔티티: `parseSuccess`, `parseFailReason` 필드 제거
- API 엔드포인트: `/transactions/failed` → `/transactions/parse-failures`, `/transactions/successful` → `/transactions/by-date`
- `CardTransactionResponse`: `parseSuccess` 제거, `cardLastFourDigits` 추가
- `TelegramNotificationService`: `notifyParseFailure(CardParseFailure)` 메서드 추가
- 프론트엔드: 탭 구조 `전체/성공/실패` → `거래내역/파싱실패`로 변경

### DDL

```sql
CREATE TABLE aguagu.card_parse_failures (
    id BIGSERIAL PRIMARY KEY,
    phone_number VARCHAR(20),
    card_company VARCHAR(20) NOT NULL,
    raw_message TEXT NOT NULL,
    fail_reason VARCHAR(500) NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_parse_failure_created_at ON aguagu.card_parse_failures(created_at);
CREATE INDEX idx_parse_failure_card_company ON aguagu.card_parse_failures(card_company);

-- 기존 테이블 정리
DELETE FROM aguagu.card_transactions WHERE parse_success = false;
ALTER TABLE aguagu.card_transactions DROP COLUMN parse_success;
ALTER TABLE aguagu.card_transactions DROP COLUMN parse_fail_reason;
DROP INDEX IF EXISTS aguagu.idx_parse_success;
```
