## 1. 신용카드(CreditCard) 테이블 분리 및 관리 기능 구현

신용카드 정보를 별도 테이블(`credit_cards`)로 분리하고, 한도 관리·거래 저장이 등록된 신용카드를 기반으로 동작하도록 변경.

### DB 스키마

```sql
CREATE TABLE aguagu.credit_cards (
    id                VARCHAR(30)  PRIMARY KEY,   -- "SAMSUNG_4300"
    card_company      VARCHAR(20)  NOT NULL,
    last_four_digits  VARCHAR(4)   NOT NULL,
    billing_start_day INT          NOT NULL DEFAULT 1,
    billing_end_day   INT          NOT NULL DEFAULT 31,
    created_at        TIMESTAMP    NOT NULL DEFAULT NOW(),
    updated_at        TIMESTAMP    NOT NULL DEFAULT NOW(),
    UNIQUE (card_company, last_four_digits)
);
```

### 백엔드 신규 파일

| 파일 | 설명 |
|------|------|
| `entity/CreditCard.kt` | JPA 엔티티, PK = `{COMPANY}_{digits}` |
| `repository/CreditCardRepository.kt` | CRUD + 마스킹 변형 매칭 |
| `dto/CreditCardDto.kt` | Request/Response DTO |
| `service/CreditCardService.kt` | 등록/조회/삭제 + `findByCardInfo()` 마스킹 변형 매칭 |
| `controller/CreditCardController.kt` | REST API `/api/v1/card/credit-cards` |

### 백엔드 수정 파일

| 파일 | 변경 내용 |
|------|-----------|
| `CardLimitDto.kt` | `cardCompany`+`cardLastFourDigits` → `creditCardId` 기반으로 변경 |
| `CardLimitService.kt` | CreditCard 연동, 정산 기간 계산 로직 (`calculateBillingPeriod`) 추가 |
| `CardTransactionService.kt` | 파싱 후 CreditCard 자동 매칭, 원본 끝4자리로 저장 |

### 프론트엔드

- `CreditCardListView.vue` 신규 (카드 등록/조회/삭제)
- `LimitListView.vue` 수정 (카드사+끝4자리 직접 입력 → CreditCard 셀렉트박스)
- `api/index.js`, `router/index.js`, `DefaultLayout.vue` 수정

### 핵심 로직

**정산 기간 계산** (`CardLimitService.calculateBillingPeriod`):
```
예: billingStartDay=15, billingEndDay=14
  → 오늘이 1/20이면: 1/15 ~ 2/14
  → 오늘이 1/10이면: 12/15 ~ 1/14
CreditCard 미등록 시 기본 월초~월말 폴백
```

**파싱 시 CreditCard 매칭**:
- 마스킹 변형 고려 (하나카드 `7*2*` → `7921` 매칭)
- 매칭 시 원본 끝4자리로 저장, 미등록 카드도 정상 저장

## 2. 카드 한도 3종류 (월간/연간/커스텀) 확장

기존 `monthlyLimit` 단일 한도를 MONTHLY, YEARLY, CUSTOM 3종류로 확장.

### 신규 파일

| 파일 | 설명 |
|------|------|
| `common/enums/LimitType.kt` | `MONTHLY`, `YEARLY`, `CUSTOM` 열거형 |

### DB 마이그레이션

```sql
ALTER TABLE aguagu.card_limits ADD COLUMN limit_type VARCHAR(20) NOT NULL DEFAULT 'MONTHLY';
ALTER TABLE aguagu.card_limits RENAME COLUMN monthly_limit TO limit_amount;
ALTER TABLE aguagu.card_limits ADD COLUMN custom_start_date DATE;
ALTER TABLE aguagu.card_limits ADD COLUMN custom_end_date DATE;
```

### 기간 계산 로직

| 유형 | 기간 계산 방식 |
|------|---------------|
| **MONTHLY** | CreditCard의 billingStartDay/billingEndDay 기반 정산 기간, 없으면 1일~말일 |
| **YEARLY** | 현재 년 1월 1일 ~ 12월 31일 |
| **CUSTOM** | customStartDate ~ customEndDate |

### 수정 파일

| 파일 | 변경 내용 |
|------|-----------|
| `entity/CardLimit.kt` | `monthlyLimit` → `limitAmount`, `limitType`, `customStartDate`, `customEndDate` 추가 |
| `dto/CardLimitDto.kt` | Request/Response에 `limitType`, 커스텀 날짜 필드 추가 |
| `service/CardLimitService.kt` | `calculatePeriod()` limitType별 분기, CUSTOM 검증 |
| `notification/TelegramNotificationService.kt` | limitType.displayName 기반 동적 표시 |
| `front/src/views/LimitListView.vue` | 유형 셀렉트, 커스텀 날짜 입력, 유형 컬럼(색상 칩) 추가 |
